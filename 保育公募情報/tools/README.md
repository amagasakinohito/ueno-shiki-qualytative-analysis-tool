# 巡回スクリプト

各市のHPを毎日巡回して、**新しく出た公募情報だけ**をガルーンに投稿します。

## ⚠️ どこまで検証済みか

**確認できていること**（ローカルにテスト用サイトを立てて実行）

- 自治体サイト風のHTMLから、公募に関係する行とリンクだけを抜き出せること
- ナビゲーション・フッター・更新日時・アクセスカウンタが除外されること
- 新着リンク／新着行／掲載が消えた行を検知できること
- 同じ項目がリンクと行で二重に報告されないこと
- Shift_JIS のページを文字化けせず読めること
- 404 はリトライせず、失敗として報告されること
- 取得に失敗したページの状態は更新されないこと
- ガルーンへ送るJSONが、改行・引用符・バックスラッシュを含む本文でも壊れないこと
- 長い本文が分割投稿されること
- 設定漏れや非ASCIIのUser-Agentが分かりやすいエラーで止まること

**確認できていないこと**

- **実際の各市サイトに対する動作**。開発環境から各市サイトへのアクセスが
  ネットワークポリシーで遮断されており（全て403）、本物のHTMLで試せていません。
- **実際のガルーンへの投稿**。同じ理由で接続できません。

したがって、**社内で動かす際は必ず `--dry-run` から始めて**、期待どおりの結果が
出ることを確認してから自動実行に移してください。特に次の2点は環境依存で調整が要ります。

- 各市サイトの**本文領域の切り出し**（`sources.yaml` の `selector`）
- ガルーンの**投稿先エンドポイント**（`config.ini` の `endpoint` / `body_template`）

---

## 必要なもの

- Python 3.10 以上
- 各市サイトとガルーンに到達できるネットワーク
- ガルーンの**投稿用アカウント**と、投稿先への**書き込み権限**

## セットアップ

```bash
cd 保育公募情報/tools

# 依存ライブラリ
pip install -r requirements.txt

# 設定ファイルを作る
cp config.example.ini config.ini
# config.ini を編集（base_url / login / password / endpoint / body_template）
```

`config.ini` はパスワードを含むため `.gitignore` で除外しています。コミットしないでください。

## 動かし方

### 1. まず巡回だけ試す（投稿しない）

```bash
python watch.py --dry-run
```

全ページを取得して、拾えた内容を画面に出します。
**ここで各市のページがきちんと取れているかを確認します。**
取得に失敗したページは「取得できなかったページ」として一覧に出ます。

1市だけ試したいときは `--only` を使います。

```bash
python watch.py --dry-run --only 大阪市
```

### 2. ガルーンの接続を確認する

```bash
python garoon.py --check       # 接続と認証だけ確認
python garoon.py --test-post   # テストメッセージを実際に投稿
```

### 3. 現状を基準として記録する

```bash
python watch.py --init
```

**初回に1度だけ実行します。** 今ページに載っている内容を「既知」として記録し、
次回以降はそこからの差分だけを報告します。これをやらずに始めると、
初回に全ページの全項目が「新着」として投稿されてしまいます。

### 4. 本番運用

```bash
python watch.py
```

差分があればガルーンに投稿し、なければ何もしません。

## 定時実行の登録

**Windows（タスクスケジューラ）**

`run_daily.bat` を「基本タスクの作成」→ トリガー「毎日 8:00」→
操作「プログラムの開始」で指定します。ログは同じフォルダの `watch.log` に追記されます。

**macOS / Linux / 社内サーバ（cron）**

```
0 8 * * * /path/to/保育公募情報/tools/run_daily.sh >> /path/to/watch.log 2>&1
```

社内サーバに置けるなら、PCの電源状態に左右されないのでそちらを推奨します。

## オプション

| オプション | 説明 |
|---|---|
| `--dry-run` | 投稿せず結果を画面に出す |
| `--init` | 現状を基準として記録するだけ（初回に1度） |
| `--only 市名` | 特定の市だけ巡回する |
| `--post-always` | 変更がなくても投稿する（週次リマインド用） |
| `--report-file PATH` | レポートをファイルにも保存する |
| `--sources PATH` | 巡回対象の定義ファイルを差し替える |
| `--state PATH` | 状態ファイルの場所を変える |
| `-v` | 詳しいログを出す |

週1回だけ「変更なし」も含めて報告したい場合は、月曜だけ別枠で登録します。

```
0 8 * * 1 /path/to/run_daily.sh --post-always
```

## 仕組み

### 差分の取り方

HTML全体を比較すると、更新日時やバナーの入れ替えで毎回「変更あり」になってしまいます。
そこで本文から次の2つだけを抜き出して比較しています。

1. 「募集」「公募」「プロポーザル」「選定」「指定管理」などのキーワードを含む**行**
2. 同じキーワードを含む**リンク**（リンク文字列とURL）

これにより、リンクで案内されるタイプのページ（大阪市・豊中市）と、
本文に直接書かれるタイプのページ（西宮市・宝塚市）の両方に対応できます。

キーワードは `watch.py` の `KEYWORDS` にあります。取りこぼしがあれば追加し、
ノイズが多ければ削ってください。

### 状態ファイル

`state.json` に前回取得した行とリンクを保存しています。
これを消すと次回が初回扱いになり、全項目が新着として出ます。
（消してしまった場合は `--init` で基準を取り直してください）

**取得に失敗したページの状態は更新しません。** 一時的な障害で状態が
空になり、復旧時に全件が新着として流れるのを防ぐためです。

### 投稿しない日

変更が何もなければ投稿しません。毎日同じ投稿が積まれると読まれなくなるためです。
ただし**取得に失敗したページがある場合は投稿します** — 監視が止まっていることに
気づけないと、公募を見逃す原因になるからです。

## 監視対象を増やす・減らす

`sources.yaml` を編集します。1エントリの形式は次のとおりです。

```yaml
  - city: 西宮市
    category: 保育所
    name: 保育施設の整備について
    url: https://www.nishi.or.jp/kosodate/hoikujo/hoikujo/hoiku_seibi/index.html
    priority: high        # high はレポートの先頭に出る
    selector: "#content"  # 任意。本文領域を絞るとノイズが減る
```

対象ページの一覧と、なぜそのページを見るのかは
[../監視対象URL一覧.md](../監視対象URL一覧.md) に整理しています。

## スクレイピングにあたっての配慮

- 取得間隔は既定で5秒。市のサーバに負荷をかけないため、短くしすぎないでください
- `user_agent` に連絡先を入れておくと、市の担当者が問い合わせできて親切です
- 各市サイトの利用規約と robots.txt をご確認ください
- 募集要項PDFを丸ごと転載せず、リンクで案内する方針にしています

## うまくいかないとき

**取得できないページがある**
URLが変わっている可能性があります。市のサイトはリニューアルでURLが変わりがちです。
ブラウザで開いて確認し、`sources.yaml` を直してください。

**新着が多すぎる／ノイズが多い**
`sources.yaml` にそのページの `selector` を足して本文領域を絞るか、
`watch.py` の `KEYWORDS` を減らしてください。

**新着を取りこぼす**
逆に `KEYWORDS` を足してください。ただし「事業者」「受付」のような
一般的すぎる語を入れるとノイズが増えます。

**ガルーンに投稿できない**
`python garoon.py --check` で接続と認証を切り分けてください。
HTTP 401 なら認証、403 なら書き込み権限、404 なら `endpoint` の指定が疑わしいです。
投稿に失敗した場合、レポート内容は画面に出力されるので失われません。
