# 巡回スクリプト

7市のHPを毎日巡回して、**新しく出た公募情報だけ**をガルーンのスペースに自動投稿します。

## 使い始め方

Python がまだ入っていなければ [python.org](https://www.python.org/downloads/) から入れてください
（Windowsのインストール画面では **「Add Python to PATH」にチェック**を入れてください）。

あとは、このフォルダで次の1行を実行するだけです。

```
python setup.py
```

聞かれるのは**ガルーンのログイン名とパスワードだけ**です。残りは全部自動でやります。

1. 必要なライブラリのインストール
2. `config.ini` の作成
3. ガルーンへの接続確認
4. 投稿できる形式を自動判定してテスト投稿（スペースに1件届きます。削除して構いません）
5. 各市サイトの巡回と、現在の掲載内容の記録
6. 毎朝8時の自動実行を登録

これで完了です。明日の朝から、新しい公募情報があれば自動で投稿されます。
**変更がない日は投稿しません。**

途中で失敗しても、原因と次にやることが日本語で表示されます。

### 投稿先

`config.example.ini` に設定済みです。

- ガルーン: `https://ainosono.cybozu.com`（クラウド版）
- 投稿先: スペースID **282** / ディスカッションID **1453**

別のスペースに変えたい場合は、ガルーンでそのスペースを開いてURLを見てください。
`?spid=282#tid=1453` の数字が、そのままスペースIDとディスカッションIDです。

## 普段使うコマンド

| やりたいこと | コマンド |
|---|---|
| 今すぐ巡回して結果を画面で見る（投稿しない） | `python watch.py --dry-run` |
| 今すぐ巡回して投稿する | `python watch.py` |
| 1つの市だけ試す | `python watch.py --dry-run --only 大阪市` |
| 自動実行をやめる（Windows） | `schtasks /Delete /TN "保育公募情報巡回" /F` |
| 自動実行をやめる（Mac/Linux） | `crontab -e` でその行を削除 |

監視しているページの一覧と、なぜそのページを見るのかは
[../監視対象URL一覧.md](../監視対象URL一覧.md) にまとめています。
増やしたり減らしたりしたい場合は `sources.yaml` を編集してください。

## 困ったとき

**「取得できなかったページ」が投稿に出る**
市のサイトがリニューアルしてURLが変わった可能性が高いです。
そのページ名を伝えていただければ調べて直します。放っておくとそのページの
公募を見逃すので、出たら対応が必要です。

**投稿が来ない**
`python watch.py --dry-run` を実行してみてください。
「変更 0件」なら正常（本当に新着がないだけ）です。エラーが出ていれば、
その内容をそのまま伝えてください。

**投稿が多すぎる／関係ない内容が混ざる**
`sources.yaml` の該当ページに `selector` を足して本文領域を絞るか、
`watch.py` の `KEYWORDS` を減らします。伝えていただければ調整します。

**パスワードを変えた**
`python setup.py` をもう一度実行してください。作り直すか聞かれます。

## 仕組み（技術メモ）

### 差分の取り方

HTML全体を比較すると、更新日時やバナーの入れ替えで毎回「変更あり」になってしまいます。
そこで本文から次の2つだけを抜き出して比較しています。

1. 「募集」「公募」「プロポーザル」「選定」「指定管理」などのキーワードを含む**行**
2. 同じキーワードを含む**リンク**（リンク文字列とURL）

これにより、リンクで案内するタイプのページ（大阪市・豊中市）と、
本文に直接書くタイプのページ（西宮市・宝塚市）の両方に対応できます。

### 状態ファイル

`state.json` に前回取得した行とリンクを保存しています。
消すと次回が初回扱いになり全項目が新着として出るので、消してしまったら
`python watch.py --init` で基準を取り直してください。

**取得に失敗したページの状態は更新しません。** 一時的な障害で状態が空になり、
復旧時に全件が新着として流れるのを防ぐためです。

### 投稿しない日／する日

変更がなければ投稿しません。ただし**取得に失敗したページがある場合は投稿します** —
監視が止まっていることに気づけないと、公募を見逃す原因になるからです。

週1回だけ「変更なし」も含めて報告したい場合は `--post-always` を使います。

### スクレイピングにあたっての配慮

- 取得間隔は5秒。市のサーバに負荷をかけないため短くしすぎないでください
- `user_agent` に連絡先を入れてあると、市の担当者が問い合わせできて親切です
  （HTTPヘッダはASCIIのみなので日本語は使えません）
- 募集要項PDFを転載せず、リンクで案内する方針にしています

### ファイル構成

| ファイル | 役割 |
|---|---|
| `setup.py` | セットアップ一式 |
| `watch.py` | 巡回・差分検知・レポート生成 |
| `garoon.py` | ガルーン投稿。単体で `--check` `--test-post` も可能 |
| `sources.yaml` | 巡回対象33ページの定義 |
| `config.example.ini` | 設定の雛形 |
| `config.ini` | 実際の設定。**パスワードを含むためGitに入れていません** |
| `state.json` | 前回取得内容。同じくGitに入れていません |

## 検証状況

**ローカルに自治体サイト風のページと、ガルーンを模したサーバを立てて確認済み**

- セットアップが最初から最後まで通ること、パスワード誤りが分かりやすく止まること
- 投稿ボディの形式が自動判定され、成功した1件だけが投稿されること
- 新着リンク・新着行・消えた行を検知し、リンクと行で二重報告しないこと
- ナビ／フッター／更新日時／アクセスカウンタが除外されること
- 変更がない日は投稿せず、変更がある日は投稿すること
- Shift_JISのページを文字化けせず読めること
- 404を再試行せず、失敗ページの状態を更新しないこと

  ネットワークポリシーで遮断されており（403）、本物では試せていません。

`setup.py` は各段階で失敗を検出して止まるので、実環境で通れば動いています。
