# 毎日ガルーンの電子会議室へ自動投稿できるか（検討メモ）

## 結論

**技術的には可能。ただし「この Claude Code のセッションから毎日投稿する」形では実現できない。**
社内ネットワーク側で動く常駐の仕組み（スクリプト＋定時実行）を別に用意する必要がある。

理由は2つ。

1. **セッションは常駐しない。**
   このリポジトリを扱う実行環境は、使い終わると破棄される一時的なコンテナ。
   「毎日決まった時刻に動き続ける」用途には向かない。
2. **ネットワークが通っていない。**
   今回の調査で確認したとおり、この環境からは各市の公式サイトも cybozu.dev も
   すべて `403 Forbidden` で遮断されている。市のHPを読むことも、
   ガルーンに書き込むこともできない。

つまり「情報を集める側」と「投稿する側」の両方が塞がっている。
**仕組みは作れるが、動かす場所は社内**、という整理になる。

---

## 事前に確認が必要なこと

### 1. 「電子会議室」がガルーンのどの機能か

**ガルーンの標準機能に「電子会議室」という名前のものはない。** 社内での呼び名の可能性が高い。
実体がどれかで、使えるAPIも投稿方法も変わる。

| 実体の候補 | 見分け方 | API |
|---|---|---|
| **掲示板** | カテゴリがあり、記事に対してコメントが付く | REST APIの提供範囲は要確認。JavaScript APIでの投稿事例あり |
| **スペースのディスカッション** | 「スペース」配下でスレッドが立つ | **Garoon 6.17.0（2025年7月28日）でディスカッション追加・コメント書き込みのREST APIが追加済み** |
| **メッセージ** | 宛先を指定して送る | 同 6.17.0 でメッセージ作成APIが追加済み |

> リポジトリの既存READMEに「ガルーンの実践学会スレッド」という記述があるので、
> **スペースのディスカッション（スレッド）** の可能性が高い。ここが確定すれば実装は早い。

### 2. ガルーンがクラウド版かパッケージ版か

- **クラウド版（cybozu.com）**：外部からAPIで到達できる。ただし
  **IPアドレス制限・Basic認証・セキュアアクセス**が有効だと、その設定に合わせる必要がある
- **パッケージ版（自社サーバ）**：社内ネットワークからしか到達できないことがほとんど。
  この場合、実行場所は必然的に社内PC／社内サーバになる

### 3. API利用の権限

- ガルーンのREST APIの認証は **パスワード認証（`X-Cybozu-Authorization` ヘッダ）** または Basic認証。
  kintoneのようなAPIトークンは使えない
- **投稿用のユーザーアカウント**（できれば専用のbotアカウント）と、
  対象の掲示板／スペースへの**書き込み権限**が要る
- アカウント発行と権限付与は情報システム部門の承認が必要になるはず

## 実現方式の案（おすすめ順）

### 案A：社内PCで Python スクリプト＋タスクスケジューラ

もっとも素直。毎朝スクリプトが動いて、市のHPを巡回し、差分があればガルーンに投稿する。

```
[社内PC] 毎朝8時
   ↓ 監視対象URL一覧.md のURLを順に取得
   ↓ 前回取得分と比較して「新着・変更」だけ抽出
   ↓ 変更なしなら何もしない（毎日ゴミ投稿が積まれるのを防ぐ）
   ↓ 変更ありならガルーンREST APIで投稿
[ガルーン 電子会議室]
```

- 実行：Windowsタスクスケジューラ / macOS launchd / Linux cron
- 必要なもの：Python、`requests`、投稿用アカウント
- 弱点：**そのPCが起動していないと動かない**

### 案B：Google Apps Script（GAS）

- サーバ不要、GASのトリガーで毎日実行できる。運用がいちばん楽
- **条件：ガルーンがクラウド版で、外部（Google）からアクセスできること**
- パッケージ版・IP制限ありの場合は使えない
- GASからガルーン掲示板を読む事例は公開されており、書き込みも同じ要領

### 案C：社内サーバ／NASで cron

- 案Aの安定版。常時稼働なので取りこぼしがない
- 立てられる環境があるならこれが最善

## 投稿内容の設計（重要）

**毎日必ず投稿する形にしない。** 変更がない日が大半なので、毎日投稿すると
「またあの自動投稿か」と読まれなくなる。

推奨：

- **新着・変更があった日だけ投稿**
- 週1回（例：月曜）だけ「今週の締切が近い案件」のリマインドを投稿
- 本文には必ず **市名／区分（保育所・児童発達支援・学童）／案件名／締切／URL** を入れる

投稿本文の例：

```
【保育公募 新着】2026-08-06

■ 伊丹市（保育所）
認可保育所設置及び運営事業者の募集（令和9年4月1日開設：阪急稲野駅周辺）
締切：2026-09-30
https://www.city.itami.lg.jp/SOSIKI/KODOMO/HOIKU/bosyuu/reiwa7nendo/45945.html

■ 豊中市（学童保育）
放課後こどもクラブ運営業務 公募型プロポーザル
締切：2026-08-25
https://www.city.toyonaka.osaka.jp/jigyosya/proposal/jisshichu/index.html

（変更なし：西宮市／尼崎市／芦屋市／宝塚市／大阪市）
```

## 差分検知の作り方

各市のページはお知らせが1行増えるだけのことも多いので、HTML全体の比較だと
広告やアクセスカウンタで毎回「変更あり」になってしまう。

- ページ本文領域だけ抜き出してテキスト化し、**そのハッシュを保存して比較**する
- 過去に見た募集タイトルを一覧で持っておき、**新しいタイトルが出たときだけ通知**する方が確実
- 「受付は終了しました」の文言が付いたら **クローズ扱い**にする

保存先は、このリポジトリに `state.json` のような形で持たせても良いし、
社内PCのローカルファイルでも良い。

---

## スクレイピングにあたっての配慮

- アクセスは **1日1回・1ページずつ・間隔をあけて**。市のサーバに負荷をかけない
- 各市サイトの利用規約とrobots.txtを確認する
- 取得したPDFの募集要項を丸ごと転載せず、**リンクで案内**する

## 次のステップ

**［2026-08-17 追記］スクリプトは実装済み。[tools/](tools/) を参照。**
案Aの方式（社内PC／サーバでPythonスクリプトを定時実行）で作ってあり、
`sources.yaml` に監視対象、`config.ini` にガルーン接続情報を書けば動く。

残っているのは、環境に依存するため外から決められない次の3点。

1. 「電子会議室」がガルーンの**掲示板 / スペースのディスカッション / メッセージ**のどれか確認
   → 分かったら `config.ini` の `endpoint` と `body_template` を設定する
   （3パターンの雛形を `config.example.ini` に用意済み）
2. ガルーンが**クラウド版かパッケージ版**か、URLと合わせて確認
   → `base_url` に設定する。Basic認証・クライアント証明書・プロキシにも対応済み
3. **投稿用アカウント**の発行と書き込み権限の付与を情報システム部門に相談
   → `login` / `password` に設定する

設定後、`python garoon.py --check` で接続と認証だけを先に確認できる。
